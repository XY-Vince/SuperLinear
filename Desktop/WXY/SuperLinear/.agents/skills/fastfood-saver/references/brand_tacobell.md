# Taco Bell — 套餐架构驱动型范式

不依赖促销码也不依赖领券，把巨额优惠直接封装在 **App 独占自选套餐** 与平价价值菜单的**架构**里。省钱的关键是"怎么点"，不是"输什么码"。

## 机制要点

- **App 独占自选盒（Cravings Box 类）**：仅 App/线上可见可点的自选套餐（自选主品 + 配菜 + 饮品等槽位），价格相对单点接近腰斩。**线下门店菜单上看不到是特性不是 bug**——用户在店里问"有没有那个盒子"经常被店员说没有，必须走 App 下单；
- **平价价值菜单（Value Menu / Cravings Value Menu）**：常驻低价单品层，$1–$3 档位组合公式可拼出极低预算一餐；
- **时段性空投**：
  - **周二类固定福利**（Taco Tuesday 类：历史上反复出现折扣/买送/免配送形态）；
  - **Happy Hour 类饮品特价**（历史上 2–5 PM 时段饮品低价反复出现）；
  - App 内不定期 Drop（限量券/新品空投），时效极短。

## 推荐路径

1. **预算极低（<$4–5）**：Value Menu 组合公式——1 主品 + 1–2 平价配菜 + 免费水，或直接上自选盒（若当前价格点更低）；
2. **单人吃好（$5–8）**：App 自选盒是默认答案——指引完整点单路径：打开 App → 菜单 → 找 Cravings Box / Build Your Own 组合 → 逐槽位自选 → 门店自提或外送；
3. **时段匹配**：用户在 2–5 PM 之间问 → 主动提饮品特价；周二问 → 主动提 Taco Tuesday 当期形态（现场搜索确认）。

## 排错速查（塔可钟版）

| 用户现象 | 定位与动作 |
|---|---|
| 店里说没有自选盒 | 正常——App 独占。指引用户 App 内下单（可自提），而不是跟店员争论 |
| 自选盒槽位选不了某品 | 槽位有品类范围限制，换槽位内可选品；个别高价品历史上会被临时移出盒子范围 |
| 价格和我上次不一样 | 自选盒价格随档位/地区/阵容调整浮动，以 App 当前结算价为准 |
| 想要更多折扣 | 查 App Drops / Rewards 积分兑换，叠加在套餐架构之上 |

## 相邻品牌（Panda Express 类同范式）

Panda Express 同属套餐架构型：App/官网有线上专属组合价与积分（chance to win 类活动历史上常见），门店菜单不展示线上组合。推荐逻辑同上：先架构（组合套餐）后时段。

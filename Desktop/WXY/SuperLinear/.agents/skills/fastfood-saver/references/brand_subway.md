# Subway — 代码驱动型范式

北美最大加盟制三明治连锁。优惠几乎全靠手动促销码，是"码失效四大维度"的重灾区品牌。

## 机制要点

- **价格分级梯队**：全国性促销常按物价区发多档码（历史上出现过的档位模式：$6.99 / $7.99 / $8.99 一尺类）。高物价区低档码必拒；
- **品类强排他**：码通常只作用于"经典基础计价款"，Series 系列、限时新品、加价配料全部排他；
- **加盟商自主权**：单店可后台关闭折扣参与，切店对比是核心排查手段；
- **语法别名**：全拼 ↔ 缩写双形态并存（如 `FOOTLONG699` 类 ↔ `699FL` / `FL699` 类模式），不同 POS / 订单通道识别不同。

## 选品白名单逻辑（防翻车核心）

给用户推荐 Subway 促销码时，**必须同时给出这份清单**（截至上次实测的结构性规律，具体品类名可能随菜单改版变动）：

**通常可用（经典基础计价款）**：
- 经典系列冷切肉款（Italian B.M.T. 类、Spicy Italian 类、Turkey 类、Ham 类、Tuna 类、Veggie Delite 类等按基础价计价的经典款）；
- 六寸 / 一尺基础规格，标准面包与标准配料范围内。

**大概率报"不可用"（推荐前主动警告）**：
- **Series 系列招牌款**（Signature/系列三明治，走独立营销定价）；
- **限时新品 / 区域限定款**；
- **加价配料**：培根、牛油果、双份肉/芝士、Premium 蛋白等任何加价项；
- 部分码排除 Protein Bowl 形态或反之——按码的描述核对。

**给用户的操作话术**："先用最普通的经典款试码确认码本身有效，确认后再在白名单内换口味，不要一次到位配复杂款。"

## 检索当前码的渠道优先级

1. Subway 官方 App / 官网 Deals 页与邮件订阅（最权威）；
2. Web 搜索 "Subway promo code" + 当前月份（RetailMeNot / Honey 类聚合站仅作参考，过期率高）；
3. Reddit r/subway 最新帖（可用 `scripts/fetch_reddit_coupons.py --brand subway`，社群对码的"鲜度"反馈最快，注意区分美国区与其他区域码）；
4. 档位备选：主码失败时顺延试更高档位码及其缩写变体。

## 历史档位与别名模式（结构知识，非当前有效码）

| 档位模式 | 全拼形态模式 | 缩写形态模式 |
|---|---|---|
| $6.99 一尺档 | `FOOTLONG699` 型 | `699FL` / `FL699` 型 |
| $7.99 一尺档 | `FOOTLONG799` 型 | `799FL` / `FL799` 型 |
| $8.99 一尺档 | 同构 | 同构 |

这些是**命名规律模板**：现场搜索到当前主码后，可按此规律推演备选档位与别名变体让用户顺延尝试。推演纪律（实测反馈过的问题，必须遵守）：

- 推演码必须标注 **【按规律推演，未验证】**；
- **禁止置信话术**："纽约命中率最高""最佳选择"这类说法无人统计过，属编造置信度——只说"值得一试的顺延顺序"；
- 推演仅限本表已文档化的档位（$6.99/$7.99/$8.99 一尺类）与别名形态（全拼 ↔ FL 缩写），**不得发明新码族**（如"双堡码"之类文档中不存在的家族）。

## 高发故障速查

| 用户现象 | 首先怀疑 |
|---|---|
| 选了 Series 款报不可用 | 维度 1 品类排他（换经典款即解） |
| 纽约/加州用户低档码被拒 | 维度 2 地区档位（顺延高档码） |
| "invalid code" 字样 | 维度 3 语法（查抄写 + 换别名/通道） |
| "not accepted at this location" | 维度 4 门店拉黑（切店对比） |
